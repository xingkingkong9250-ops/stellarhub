# 实施计划：DUP-A 感知哈希基础设施

- 父设计：`docs/superpowers/specs/2026-10-27-duplicate-detection-design.md`
- 版本：0.15.1 → 0.16.0（NO.M）
- 范围：仅 DUP-A。导入时查重提醒（DUP-B）、全库扫描（DUP-C）、W8（DUP-D）、VLM 终审（DUP-E）不在本阶段。

## 目标

1. 建立 dHash 感知哈希计算能力（64-bit，9×8 横向差分）。
2. schema v12：`images.phash` 列 + `duplicate_candidates` 表（本期只建表，写入逻辑留给 DUP-C）。
3. 导入流水线落库时写入 phash（本地 + NAS 远程同源）。
4. 单元测试覆盖哈希稳定性、区分度与导入落列。

## 实施步骤

1. **Schema v12**
   - `ALTER TABLE images ADD COLUMN phash TEXT;`
   - `CREATE TABLE duplicate_candidates (id, group_id, image_id, kind, level, score, status, created_at, updated_at)` + FK + 索引 `idx_dupcand_group` / `idx_dupcand_status`。
   - DbMigrator 版本 +1；v12 无回填（存量由 DUP-C 扫描时从 Thumb 补算）。

2. **解码能力**
   - `MagickDecoder.TryLoadFrame(Stream)`：与现有 path 版一致（MagickImageCollection → Flatten → PNG 桥接 → ImageSharp），不关闭调用方流。

3. **PerceptualHashService**
   - `TryCompute(Stream)`：ImageSharp `Image.Load<Rgba32>`；`UnknownImageFormatException` 时走 Magick 流重载；失败返回 null。
   - `TryCompute(string path)`：同构，供 DUP-C 从 Thumb 补算复用。
   - 算法：Resize(9, 8, Lanczos3) → 亮度 `(77R+150G+29B)>>8` → 逐行比较相邻列 → 位序 `y*8+x`。
   - `HammingDistance`（`BitOperations.PopCount`）、`ToHex`（16 位小写）、`TryParseHex`。

4. **导入集成**
   - `ImportService` 构造新增可选 `PerceptualHashService? hasher = null`，默认实例化。
   - 元数据探测通过后，用新的 `accessor.OpenRead(file)` 计算 phash；任何异常/不支持格式 → null，不影响导入。
   - `PendingImage.Phash` → INSERT 列表加 `phash` 列与 `$phash` 参数。

5. **测试**
   - 稳定性：同一图 PNG → JPEG(q80) 重编码、等比放大 4 倍，汉明距离 ≤ 10。
   - 区分度：棋盘图 vs 渐变图距离 > 10。
   - 纯色图退化为 0 的已知限制不写入断言（dHash 固有）。
   - hex 往返、已知 popcount 用例、垃圾字节返回 null。
   - 导入后 `SELECT phash FROM images` 非空且 16 字符。

6. **收尾**
   - csproj `<Version>` → 0.16.0；CHANGELOG 加 `[0.16.0]` DUP-A 条目。
   - 门禁：`dotnet build -c Release` 0 警告 0 错误；`dotnet test -c Release` 全绿（790 + 新增）。

## 风险与对策

- **远端多一次 OpenRead**：与现有 hash/元数据/复制多流模式一致；失败仅降级为 NULL phash，不阻断导入。
- **极小图（<9px）**：ImageSharp Resize 仍可用（放大采样），无异常路径。
- **纯色图哈希碰撞**：dHash 固有特性，靠 DUP-C 的 L2 向量层区分，不在此阶段处理。
