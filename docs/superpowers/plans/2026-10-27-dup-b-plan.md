# DUP-B 实施计划：导入时 L1 查重 + W2 日志 + 通知

- 日期：2026-10-27
- 父设计：`docs/superpowers/specs/2026-10-27-duplicate-detection-design.md` §4.3
- 版本：0.16.0（不单独升位，DUP-A~E 同属 0.16.0）

## 目标

导入时用 L1 dHash 与库内已有图片比对，命中只记录不拦截：

1. `ImportReport.Duplicates` 记录每张新图的最优命中（新图 ID、库内图 ID、两侧路径、汉明距离）。
2. W2 导入日志追加 `疑似重复（距离 N）：源路径 ↔ 库内路径`。
3. `NotificationKind.DuplicateDetected` 通知：W2 与文件监控自动导入都发布。
4. 无命中时零日志行、零通知。

## 实施步骤

1. 模型与常量：枚举、`DuplicateHit`、阈值常量。
2. `ImportService`：`ExistingSnapshot` 增加 phash 列表（`id, COALESCE(original_path, file_path), phash`）；批插入事务返回后按 `pending[i] ↔ inserted[i]` 对齐，对每张有 phash 的新图线性扫描现有索引取 ≤10 的最优距离，记录命中并把新图增量加入索引（保证同批/跨批互查，且不与自己比较）。
3. 通知链路：W2 `ImportViewModel` 与 `FileWatcherService` 在 `Duplicates.Count > 0` 时发布 `DuplicateDetected`。
4. 测试与 CHANGELOG。
5. 门禁：`dotnet build -c Release` 0 警告 0 错误；`dotnet test -c Release` 全绿。

## 风险与对策

- **线性扫描性能**：DUP-B 每次导入对库内 phash 线性比对，万级库可接受；DUP-C 的 `DuplicateScanService` 用 BK-tree 后在此复用替换。
- **纯色图退化**：纯色图 dHash 恒为 0，互相都会命中；这是 L1 的已知退化，测试统一使用渐变/棋盘图验证。
- **不重复通知**：每张新图只记一条最优命中，通知按新图数计数，避免一组 N 张图刷屏。
