# DUP-C 实施计划：全库查重扫描（L1 + L2）

- 日期：2026-10-27
- 父设计：`docs/superpowers/specs/2026-10-27-duplicate-detection-design.md` §4.1、§4.4、§4.5
- 版本：0.16.0（不单独升位，DUP-A~E 同属 0.16.0）
- 范围：只做服务层与单测，不做 W8 界面（DUP-D）

## 目标

1. `DuplicateScanService` 后台全库扫描：补算存量 phash → L1 BK-tree 近邻 → L2 同
   `model_id` 分块余弦 → 传递闭包聚类 → 写 `duplicate_candidates`。
2. 扫描可取消、有 `IProgress` 进度；取消不写候选表。
3. 新一轮扫描先清 `pending` 旧行，`resolved/dismissed` 历史保留。
4. L1 阈值沿用 `PerceptualHashService.SameImageMaxDistance = 10`；L2 阈值
   `DuplicateScanService.VariantMinCosine = 0.92`。

## 实施步骤

1. **BK-tree**：`Add(id, hash)` 以汉明距离为边；`Search(hash, maxDistance, excludeId)`
   用栈做半径查询（只下探 `[d-max, d+max]` 的边）。
2. **补算 phash**：查 `phash IS NULL/''` 的行，按 `file_hash` 定位
   `thumbnails\<hash2>\<hash>_thumb.webp`，`PerceptualHashService.TryCompute(path)`
   成功即 `UPDATE ... WHERE id AND phash IS NULL`；缩略图缺失或解码失败计入
   `ImagesWithoutPhash`。
3. **L1 配对**：加载全部有效 phash 建树；对每张图半径查询（排除自身），配对
   键规范化 `(min,max)`，距离取最小，得分 `1/(1+距离)`。
4. **L2 配对**：读 `image_embeddings`（`dim > 0`），按 `model_id` 分组；每组按
   256 条分块，块内与跨块成对算余弦，`≥0.92` 且未被 L1 覆盖时记为变体。
5. **聚类**：并查集求传递闭包；成员得分取自身 L1/L2 最优边；全员 L1 的组记为
   同图组，否则变体组。
6. **落表**：单事务内先 `DELETE ... WHERE status='pending'`，再按组插入每成员
   一行（`pending`，组 GUID，`kind/level/score`）。
7. **取消**：补算、配对、向量扫描、落表前均检查令牌；取消返回
   `Cancelled=true` 且不写候选表。
8. **测试与 CHANGELOG**，然后跑门禁。

## 验收标准

- `dotnet build -c Release` 0 警告 0 错误。
- `dotnet test -c Release --no-build` 全绿（805 基线 + 新增用例）。
- BK-tree 半径查询结果与暴力枚举逐项一致。
- A-B-C 链式近邻聚成一组；不同 `model_id` 的同向量不产生候选。
- 重扫后 `pending` 被替换，`resolved/dismissed` 保留；取消后候选表零变化。
- 缩略图补算写回 `images.phash`，缺缩略图不报错只计数。

## 风险与对策

- **L2 O(n²)**：万级库分块扫描耗时以实测为准；本轮不做 ANN，先保证正确性，
  后续如需加速在 DUP-E 后单独评估。
- **纯色图退化**：dHash 恒 0 会互相命中，属 L1 已知退化；测试用渐变/棋盘避免。
- **缩略图布局**：补算依赖 `_thumb.webp` 命名与两字符分片，直接用
  `ThumbnailService.GetThumbnailPath` 的同一规则，不新增路径知识。
